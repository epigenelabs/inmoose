# R references for unequal-df variance moderation

`reference.json` was generated by `generate.R`, without consulting Python
results. The reference functions are from canonical Bioconductor limma commit
[`02a9dbd9c97d0ac9c5003c171cb1a3809cd1f16e`](https://github.com/bioc/limma/tree/02a9dbd9c97d0ac9c5003c171cb1a3809cd1f16e).
The JSON records source checksums and R/package versions.

Generation used R 4.3.3 with limma 3.65.1, loading the current R functions into
an isolated environment. The installed package supplies `lmFit`,
`contrasts.fit`, and the compiled LOWESS kernel. The single-iteration weighted
LOWESS algorithm was checked against current `src/weighted_lowess.c`.
The current functions include the `span` argument added after limma 3.65.1.

From the repository root, with R, limma, statmod and jsonlite installed:

```sh
Rscript tests/limma/data/unequal_df/generate.R
```

An optional argument supplies a directory containing the reference R sources
instead of downloading them. Python tests read the generated JSON and need no R.

The small cases cover equal and unequal integer df, fractional df down to the
0.01 inclusion threshold, zero df, missing/nonpositive variances, prior weights,
both trend estimators, a custom span, and a likelihood optimum at the upper
search boundary. A single 211-point deterministic smoother case exercises
limma's 200-seed interpolation shortcut; small cases cover ties and the linear
regression fallback. Invalid inputs deliberately retain R's behavior, including
undefined scale when only two informative values remain after weighting.

The `missing_*.csv` inputs are copies of the ProteoFlux canonical `missing`
case. The saved R fit (including its non-estimable coefficient positions)
allows moderation to be tested independently of InMoose issue #184.
Both default and `legacy=TRUE` moderation are recorded, with and without a
trend. No committed ProteoFlux references were changed.

Tests compare estimates at relative tolerance 1e-9 and absolute tolerance
1e-12. Only prior df near the upper optimizer boundary use relative tolerance
5e-7: SciPy bounded Brent and R `optimize` use slightly different square-root
machine-epsilon constants, amplified by the transformation `df2=2*p/(1-p)`.
Posterior variances retain the tighter tolerance.

The separate `tmixture_vector` mutation of total df is intentionally not fixed.
Public `eBayes` prior estimates and t/p statistics are compared directly;
the correct total df is tested at the `squeezeVar` level.
